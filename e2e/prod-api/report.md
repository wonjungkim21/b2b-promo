# 운영 배포 백엔드 E2E 테스트 리포트

- 실행일: 2026-08-21
- 대상: `https://honghak-123-be.vercel.app` (Vercel에 배포된 백엔드, 운영 Supabase Postgres 연결)
- 기준 문서: `docs/5-user-scenario.md` v1.1 (UC-0~UC-12, 예외/엣지케이스 표 5장)
- 방법: 프론트엔드는 배포되어 있지 않아 API 레벨로 검증. Node.js(`fetch`) 스크립트로 배포된 백엔드에 직접 HTTP 요청을 보내고 응답 코드/바디를 확인. 동시성 케이스는 `Promise.all`로 2건 동시 요청.
- 사전 준비: 운영 DB가 비어 있어 `docs/10-schema.sql`로 스키마를 먼저 생성(별도 작업)한 뒤, 이번 테스트를 위해 `backend/seed.sql`과 동일한 관리자 1명 + 사용자 3명(포인트 800/2,000/5,500) + 이벤트 4건(진행중 2/예정 1/종료 1)을 운영 DB에 직접 삽입해 테스트 픽스처로 사용.
- 스크립트: `e2e/prod-api/run.mjs`(시나리오 일괄 실행), `e2e/prod-api/concurrency.mjs`(동시 응모), 원본 응답: `e2e/prod-api/results.json`

## 참고 사항 (버그 아님)

- 프론트엔드는 이 URL에 배포되어 있지 않아, 화면 캡처 없이 API 응답으로만 검증했습니다. 화면 단위 검증이 필요하면 프론트엔드 배포 URL을 알려주시면 이어서 진행할 수 있습니다.
- `/api-docs`(Swagger UI)는 `NODE_ENV=production`에서 의도적으로 비활성화되어 있어 404가 정상입니다(`backend/src/app.js` 참조).
- 테스트를 위해 운영 DB에 직접 삽입한 관리자/샘플 계정·이벤트(seed.sql과 동일 구성)가 남아 있습니다. 테스트 중 생성된 임시 이벤트 2건은 정리했고, 회원가입 테스트로 생성된 `prod-e2e-01@test.com` 계정(포인트 0)은 남아 있습니다.
- 테스트 진행에 따라 각 계정의 포인트 잔액이 실제로 차감되었습니다: `user-mid` 2,000→0, `user-high` 5,500→2,500, `user-low`는 거부만 되어 800 유지. 실제 서비스 오픈 전 초기 데이터로 리셋이 필요하면 알려주세요.
