# 프레시밀 포인트 이벤트 응모(freshmeal-point-event) 와이어프레임

버전: v1.4 (2026-08-20)
기반 문서: `docs/4-PRD.md` v1.4, `docs/5-user-scenario.md` v1.1, `docs/7-arch-diagram.md` v1.3

## 1. 개요

- 목적: PRD 4.1 화면 범위를 텍스트 기반 ASCII 레이아웃으로 표현하여, 이후 상세 화면 정의서/구현 작업의 시각적 출발점을 제공한다.
- 표현 수준: 실제 색상/폰트/픽셀 단위 디자인이 아니라, 각 화면의 영역 배치와 요소 순서만 나타낸다 (오버엔지니어링 금지).
- 반응형 원칙(PRD 8장): 반응형 웹 UI를 필수 적용하되, 사용자 화면은 모바일을 기준으로 설계하고 넓은 화면(데스크탑)에서는 콘텐츠 폭을 제한하거나 목록을 다열로 확장하는 식으로 대응한다. 관리자 화면은 데스크탑 표/리스트 레이아웃을 기준으로 설계하고, 좁은 화면(태블릿 이하)에서는 표를 카드형으로 접어(stack) 대응한다. 별도 네이티브 앱은 없으며 하나의 웹 화면이 CSS로만 반응한다. 접근성(a11y)은 범위 제외.
- 브레이크포인트(단순화): 모바일 ~767px / 데스크탑 768px 이상, 2단계만 사용한다(태블릿 별도 단계 없음).
- 공통 상단 바(AppHeader): 로그인/회원가입을 제외한 인증된 모든 화면(사용자·관리자) 최상단에 고정 노출. 좌측 로고 아이콘 + "FreshMeal" 워드마크(클릭 시 role에 따라 이벤트 목록 또는 관리자 목록으로 이동), 우측에 일반 사용자만 "내 응모 내역" 아이콘 노출(관리자는 미노출). 그 아래 화면별 보조 바(뒤로가기/로그아웃)를 별도로 둔다.
- 보조 바(TopNav): 뒤로가기는 브라우저 히스토리가 아니라 화면별로 고정된 목적지로 이동한다(이벤트 상세/내 응모 내역 → 이벤트 목록, 관리자 등록·수정/응모현황 → 관리자 목록). 이벤트 목록·관리자 목록처럼 그 자체가 목적지인 화면에는 뒤로가기 버튼을 두지 않고 로그아웃 버튼만 노출한다.

## 2. 사용자 화면 (모바일 우선)

### 2.1 회원가입 (UC-0)

화면 배경 전체를 채우고, 그 위에 최대 폭 360px의 카드를 화면 정중앙(수직·수평)에 배치한다(`docs/12-style.md` 5.7).

```
+-----------------------------+
|                             |
|        [ 로고 아이콘 ]      |
|         FreshMeal           |
|                             |
| 이름       [____________]   |
| 로그인ID   [____________]   |
| 비밀번호   [____________]   |
| 비밀번호확인[____________]   |
|                             |
| [ 오류 메시지 영역 (있을 때) ]|
|                             |
|      [   가입하기   ]       |
|                             |
| 이미 계정이 있나요? 로그인   |
|                             |
+-----------------------------+
```
- 필수 입력값(name, loginId, 비밀번호)을 세로로 배치. 가입 성공 시 로그인 화면으로 이동(UC-0 3.1-1).
- loginId 중복 시 오류 메시지 영역에 안내 표시, 계정 미생성(UC-0 3.1-2).

### 2.2 로그인 (UC-1)

회원가입과 동일하게 화면 정중앙 카드 레이아웃을 사용한다.

```
+-----------------------------+
|                             |
|        [ 로고 아이콘 ]      |
|         FreshMeal           |
|                             |
| 로그인ID   [____________]   |
| 비밀번호   [____________]   |
|                             |
| [ 인증 실패 오류 메시지 ]    |
|                             |
|      [   로그인   ]         |
|                             |
| 계정이 없나요? 회원가입      |
|                             |
+-----------------------------+
```
- 로그인 성공 시 Access/Refresh Token 발급 후 role에 따라 이벤트 목록(사용자) 또는 관리자 이벤트 목록(관리자)으로 이동(UC-1 3.2-1).
- 인증 실패 시 오류 메시지만 표시, 토큰 미발급(UC-1 3.2-2).

### 2.3 이벤트 목록 (UC-2, UC-4)

SVG 샘플(모바일 뷰): [`assets/8-wireframe-event-list.svg`](assets/8-wireframe-event-list.svg)

```
+-----------------------------+
| [로고] FreshMeal    [내 응모]| <- AppHeader(공통): 로고/워드마크 + 내 응모 내역 아이콘
+-----------------------------+
|                    [로그아웃]| <- TopNav: 이 화면은 목적지이므로 뒤로가기 버튼 없음
+-----------------------------+
| ( 보유 포인트 1,500 P )      | <- PointBalanceBadge, 알약형 배지로 강조(UC-4 3.5-1)
+-----------------------------+
| [진행중] 여름 특가 이벤트    | <- EventCard(제목 bold+기간 semibold) + StatusBadge
| 07.01 ~ 08.31          >    |
+-----------------------------+
| [예정]   가을 신메뉴 이벤트  |
| 09.01 ~ 09.30          >    |
+-----------------------------+
| [진행중] 재구매 포인트 2배   |
| 08.01 ~ 08.20          >    |
+-----------------------------+
```
- 보유 포인트 배지 상시 노출(UC-4 3.5-1). 카드 목록은 status가 `진행중`/`예정`인 이벤트만 노출, `종료`는 제외(UC-2 3.3-1).
- 카드 클릭 시 이벤트 상세로 이동. 내 응모 내역 진입은 AppHeader 우측 아이콘 하나로 통일(하단 메뉴 없음).
- 상태 배지 색상: `진행중`은 진한 그린 배경+흰 텍스트, `예정`은 연한 그린 배경+진한 그린 텍스트로 대비를 확보해 두 상태 모두 한눈에 구분되게 한다(`docs/12-style.md` 2장).

**데스크탑 뷰(768px 이상)**: 동일한 EventCard를 3열 그리드로 배치한다. 콘텐츠 최대 폭을 제한해 카드가 과도하게 늘어나지 않게 한다. AppHeader/TopNav 배치는 모바일과 동일(별도 데스크탑 내비게이션 없음).

```
+-----------------------------------------------------------------+
| [로고] FreshMeal                                     [내 응모]  |
+-----------------------------------------------------------------+
| ( 보유 포인트 1,500 P )                              [로그아웃] |
+-----------------------------------------------------------------+
| [진행중] 여름 특가       | [예정] 가을 신메뉴    | [진행중] 재구매|
| 07.01~08.31         >   | 09.01~09.30       >  | 08.01~08.20  >|
+-----------------------------------------------------------------+
```

### 2.4 이벤트 상세 — 정상 (UC-3, UC-4, UC-5, UC-6, UC-7)

```
+-----------------------------+
| [로고] FreshMeal             | <- AppHeader
+-----------------------------+
| [ ← 뒤로 ]        [로그아웃]| <- TopNav: 뒤로가기는 항상 이벤트 목록("/")으로 이동
+-----------------------------+
| ( 보유 포인트 1,500 P )      |
+-----------------------------+
| [ 이벤트 이미지 (있는 경우) ]| <- 섹션1: 제목/기간
| 여름 특가 이벤트   [진행중] |
| 기간 07.01 ~ 08.31           |
+-----------------------------+
| 경품/혜택                    | <- 섹션2: 경품/혜택(있을 때만)
| 스타벅스 기프티콘             |
+-----------------------------+
| 응모 정보                     | <- 섹션3: 최대 응모 가능 횟수~미리보기
| 최대 응모 가능 횟수: 1회      |
| 응모 횟수  [ - ] [ 1 ] [ + ] |
| 사용 예정 포인트: 1,000 P    |
| 응모 후 잔여 포인트: 500 P   |
+-----------------------------+
|      [   응모 확정   ]       | <- 섹션4: 응모 확정(UC-7)
+-----------------------------+
```
- 가독성을 위해 (1) 제목/기간 (2) 경품/혜택 (3) 응모 정보(최대 응모 가능 횟수~포인트 미리보기) (4) 응모 확정, 총 4개 카드형 섹션으로 시각적으로 구분한다(둥근 모서리 12px + 연한 테두리, 섹션 간 16px 간격). 세로 배치 순서 자체는 UC-5→UC-6→UC-7 흐름을 그대로 따른다.
- **응모 확정 클릭 시 확인창**: 버튼 클릭 즉시 응모되지 않고 "응모 후에는 취소할 수 없습니다. 응모하시겠습니까?" 확인창(브라우저 네이티브 confirm)을 먼저 띄운다. 취소를 선택하면 요청 자체가 서버로 전송되지 않고, 확인을 선택해야 실제 응모 트랜잭션이 진행된다.
- 응모 확정 후 원자적 트랜잭션 처리 결과(갱신된 잔여 포인트, 누적 응모 횟수)를 섹션4 영역에 갱신 표시(UC-7 3.8-1, 도메인 5.4/5.5/5.7).

**데스크탑 뷰(768px 이상)**: 4개 섹션을 좌우 분할 없이 동일하게 세로로 쌓되, 콘텐츠 최대 폭만 제한한다(별도 2단 배치 없음).

### 2.5 이벤트 상세 — 예외: 포인트 부족/부족 임박 (도메인 5.2, UC-5 3.6-2)

```
+-----------------------------+
| [ ← 뒤로 ]        [로그아웃]|
+-----------------------------+
| ( 보유 포인트 800 P )        |
+-----------------------------+
| [ 이벤트 이미지 ]            |
| 여름 특가 이벤트   [진행중] |
| 기간 07.01 ~ 08.31           |
+-----------------------------+
| 최대 응모 가능 횟수: 0회     | <- 800P < 1,000P → 0회
| ⚠ 포인트가 부족하여          |
|   응모할 수 없습니다.         |
+-----------------------------+
| 응모 횟수  [ - ] [ 0 ] [ + ] | <- 입력 비활성(disabled)
|                             |
| 사용 예정 포인트: -          |
| 응모 후 잔여 포인트: -       |
+-----------------------------+
|   [   응모 확정 (비활성)   ]| <- 회색/클릭 불가
+-----------------------------+
```
- 보유 포인트가 1,000 미만이면 최대 응모 가능 횟수 0회 + 안내 문구 표시, 횟수 입력란과 응모 확정 버튼을 비활성화해 응모 자체를 막는다(UC-5 3.6-2, 도메인 5.2).
- 횟수를 선택했더라도 확정 시점에 보유 포인트 < 선택 횟수×1,000이면 서버가 차감 없이 거부하고 동일한 부족 안내를 표시한다(UC-7 3.8-2).

## 3. 관리자 화면 (데스크탑 우선)

### 3.1 관리자 이벤트 목록 (UC-9, UC-10, UC-11)

```
+---------------------------------------------------------------------+
| [로고] FreshMeal                                          [로그아웃]| <- AppHeader+TopNav(뒤로가기 없음, 관리자 목록 자체가 목적지)
+---------------------------------------------------------------------+
| 이벤트 관리                                          [ + 이벤트 등록 ]|
+---------------------------------------------------------------------+
| 이벤트명       | 기간              | 상태   | 응모현황 | 관리         |
|----------------|-------------------|--------|----------|--------------|
| 여름 특가 이벤트| 07.01 ~ 08.31     |[진행중]| 보기 >   | 수정 | 상태변경|
| 가을 신메뉴 이벤트|09.01 ~ 09.30    |[예정]  | 보기 >   | 수정 | 상태변경|
| 봄맞이 이벤트   | 03.01 ~ 05.01     |[종료]  | 보기 >   | 수정         |
+---------------------------------------------------------------------+
```
- 표 형태 목록에 상태 배지, 응모현황(UC-12) 진입 링크, 수정(UC-10), 상태변경(UC-11) 액션을 행별로 배치.
- 상단 "이벤트 등록" 버튼으로 등록 화면(UC-9) 진입. 상태변경은 `예정→진행중→종료`만 허용하고 역방향/건너뛰기는 UI에서 선택지 자체를 제공하지 않거나 서버 거부 메시지로 처리(도메인 3.2, 4.3-3/4.3-4).

**좁은 화면 뷰(767px 이하)**: 관리자 기능은 데스크탑 사용을 기본 전제로 하지만(PRD 8장), 반응형 원칙상 표는 행별 카드로 접어(stack) 최소한의 사용성을 보장한다.

```
+-----------------------------+
| [로고] FreshMeal  [로그아웃]|
+-----------------------------+
| 이벤트 관리      [+ 등록]   |
+-----------------------------+
| 여름 특가 이벤트   [진행중] |
| 07.01 ~ 08.31                |
| 응모현황 | 수정 | 상태변경  |
+-----------------------------+
```

### 3.2 관리자 이벤트 등록/수정 (UC-9, UC-10)

```
+---------------------------------------------------------------------+
| [로고] FreshMeal                                          [로그아웃]|
+---------------------------------------------------------------------+
| [ ← 뒤로 ]              이벤트 등록 / 수정                          | <- 뒤로가기는 항상 관리자 목록("/admin")으로 이동
+---------------------------------------------------------------------+
| 이벤트명 *     [_____________________________]                     |
| 이미지 URL(선택)[_____________________________]                    | <- 파일 업로드 백엔드가 없어 URL 텍스트 입력으로 구현
| 시작일시 *     [____________]   종료일시 * [____________]           |
| 상태 *         ( ) 예정  ( ) 진행중  ( ) 종료                        | <- 등록 화면에서만 노출(수정 화면은 상태 필드 없음, 아래 참고)
| 경품/혜택(선택)[_____________________________]                     |
|                                                                       |
| [ 유효성 오류 메시지 영역 (필수값 누락 / 종료<=시작 등) ]             |
|                                                                       |
|                                     [ 취소 ]   [ 저장 ]              |
+---------------------------------------------------------------------+
```
- 필수(*) 항목: 이벤트명/기간. 등록 화면에서는 상태(*)도 필수. 이미지·경품/혜택은 선택 입력(UC-9 4.1-1, UC-10 4.2-1).
- 이미지는 파일 업로드가 아니라 이미지 URL을 직접 입력하는 텍스트 필드로 구현한다(파일 스토리지/업로드 백엔드가 MVP 범위 밖이므로).
- 수정 화면(UC-10)에는 상태 라디오를 노출하지 않는다. 백엔드 `PUT /events/:id`가 상태 필드를 받지 않으며, 상태 전이는 3.1의 "상태변경" 액션(`PATCH /events/:id/status`, UC-11)으로만 이뤄진다.
- 필수값 누락 또는 종료일시 ≤ 시작일시면 저장 거부하고 오류 메시지 표시, 등록/수정 화면 모두 동일 규칙 적용(UC-9 4.1-2, UC-10 4.2-2, 도메인 3.2).

### 3.3 관리자 이벤트별 응모 현황 (UC-12)

```
+---------------------------------------------------------------------+
| [로고] FreshMeal                                          [로그아웃]|
+---------------------------------------------------------------------+
| [ ← 뒤로 ]        여름 특가 이벤트 - 응모 현황                       | <- 뒤로가기는 항상 관리자 목록("/admin")으로 이동
+---------------------------------------------------------------------+
| 전체 응모 횟수(SUM totalCount) : 128 회                              |
| 참여 사용자 수(row count)      : 64 명                               |
+---------------------------------------------------------------------+
```
- 이벤트 목록에서 "보기" 클릭 시 진입, 전체 응모 횟수와 참여 사용자 수 2개 지표만 단순 표시(UC-12 4.4-1).
